# Contributing

## Принцип

Изменение должно усиливать систему, а не добавлять единичный визуальный приём. Перед pull request проверьте соответствие Brand Foundation, токенам, Route Line и правилам логотипа.

## Процесс

1. Создайте короткую ветку от актуального `main`.
2. Для нового носителя добавьте или обновите template и пример применения.
3. Для нового generated asset сохраните versioned prompt и укажите его статус.
4. Не коммитьте временные архивы, base64-части, экспортные дубли и секреты.
5. Обновите `CHANGELOG.md`, если меняются core rules, tokens или официальные assets.
6. Запустите QA: JSON, внутренние ссылки, markdown, размеры exports и отсутствие запрещённых logo variants.

## Защищённые элементы

Без отдельного согласования нельзя:

- заменять четыре файла в `assets/brand/`;
- менять геометрию Full CU logo или Compact CU mark;
- добавлять цветные версии логотипа;
- менять core palette, spacing base или canonical formats;
- объявлять шрифт официальным без подтверждённого источника ЦУ.

## Definition of done

Изменение воспроизводимо, редактируемо, доступно, не содержит фактических данных внутри сгенерированного изображения и проходит preflight из `docs/12-production-workflow.md`.
